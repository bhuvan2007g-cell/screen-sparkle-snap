# PawMatch

A full-stack pet adoption and care platform: adopters browse and apply, owners and rescue
organizations list pets and review applications, and admins moderate the platform.

Built with React + TypeScript, TanStack Start, Tailwind CSS and Lovable Cloud
(PostgreSQL database, authentication, storage — powered by Supabase under the hood).

## Running locally

```bash
bun install
bun run dev      # http://localhost:8080
bun run build    # production build
```

Environment variables live in `.env` and are generated by Lovable Cloud:

| Variable | Purpose |
| --- | --- |
| `VITE_SUPABASE_URL` | Backend API URL |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | Public client key (safe in the browser) |
| `VITE_SUPABASE_PROJECT_ID` | Project reference |

Never place service keys or private secrets in client code.

## Database

All schema lives in `drizzle/migrations/` and is applied to the cloud database automatically.

Tables: `profiles`, `user_roles`, `organizations`, `pets`, `pet_images`, `favorites`,
`adoption_applications`, `notifications`, `reports`.

Key rules enforced in the database (not just the UI):

- Row Level Security on every table.
- Only accounts with role `owner` or `organization` (and not suspended) can create pets.
- Owners can edit/delete only their own pets and only see applications for their own pets.
- Adopters can read only their own applications; a unique index blocks duplicate active
  applications for the same pet.
- Approving an application automatically marks the pet `adopted`, rejects competing
  applications and notifies the adopter; new applications notify the owner.
- Indexes on species, breed, city, status, owner_id, adopter_id and created_at.

## Storage

Pet photos go to the private `pet-images` bucket, one folder per user id. Uploads are limited
to JPG/PNG/WebP/AVIF, 5 MB per file and 6 photos per pet. The app reads photos through
short-lived signed URLs; the first photo uploaded becomes the primary image.

## Authentication

Email + password sign-in is enabled. Registration collects full name, email, password, phone,
city and account type (adopter / owner / organization) and creates the matching profile row.
Email confirmation is on by default — new users confirm via the emailed link before signing in.
The signup redirect points at `/dashboard`.

## Creating an admin

Admin rights are stored in `user_roles` (never on the profile) and checked by the
`public.has_role` security-definer function. After the user has registered, run:

```sql
insert into public.user_roles (user_id, role)
select id, 'admin' from auth.users where email = 'admin@example.com';
```

The admin console is then available at `/admin`.

## Deployment

Publish from Lovable; the production build runs on the edge with the same cloud backend.
Auth redirect URLs and storage configuration are managed in the Cloud settings.
